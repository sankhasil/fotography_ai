### Verification — the part that mattered
- Ran the plan against the operator's **209 real NEFs** instead of trusting the draft
- Found the files are `NEFCompression = 14` = **High Efficiency\*** (Nikon/intoPIX TicoRAW)
- **No open-source decoder exists.** Verified failures:
  - LibRaw 0.22.1 (newest, via rawpy 0.27.1) — fails at `identify()`
  - darktable-cli 4.2.1 / 5.0.1 / **5.6.1** — all `rawspeed: Out of bounds access`
- **Then found the unblock: macOS 26.6.2 ImageIO decodes HE\* natively.**
  `sips -s format jpeg` → 8256×5504, 10.4 MB, 0 % highlight clipping. Undocumented by Apple.
- Falsified 5 plan assumptions: exiftool unnecessary, rawpy fallback dead,
  face detection infeasible (best preview 384×256), landscape rule fires 0× on a f/4-6.3 lens,
  macro rule conflates wide with close-up
- Ruled out, with evidence: **NX Studio** (no CLI — zero `--flags` in the binary, no Linux build,
  no AppleScript, "Reproduction: Not permitted") and **Adobe DNG Converter under Wine**
  (1.8 GB, five attempts, all `c0000018`)

### Bugs found and fixed
1. `_read_ifd` received the entry tuple instead of the int offset
2. **Shutter inverted** — `ExposureTime` is the duration; the reciprocal was being taken
3. Unclassified vs failed conflated by testing `correction` emptiness
4. **darktable writes `_01.jpg` when the target exists** → we hashed the *stale* file and
   reported a correction that never happened. No overwrite flag exists in 5.6.1.
5. `--category unclassified` was offered; redundant since omitting it means the same
6. `main()` raised `SystemExit` instead of returning an int

## Key contract facts (do not re-derive these)
- `darktable-cli <INPUT> <OUTPUT_DIR> [OPTIONS]` — I/O is **positional**; `-i`/`-o` do not exist
- **One `--core` flag only.** Multiple modules are semicolon-separated inside a single argument
- No `--config` flag; use `XDG_CONFIG_HOME` (darktable reads `$XDG_CONFIG_HOME/darktable/`)
- `--style` resolves against the library DB, **not** loose `.dtstyle` files
- `exiftool -Compression` reports HE\* misleadingly as `Nikon NEF Compressed`.
  **Use `-NEFCompression`** — that is the authoritative tag
- ~7 s per 45 MP render → ~24 min for 209 files

## What's pending
- **Full 209-file run** (~30 min, 56 renders). Not started — operator paused here
- **Classification accuracy is the open design question.** `night` means "ISO ≥ 3200", not "night".
  A daylight dog photo at ISO 25600 was classified `night`. Options: raise the threshold,
  add a `--category` sweep, or accept it
- Preset parameter magnitudes are **provisional** — `presets.md` fixes names/structure/order only.
  Tuning is visual iteration against real photographs and has not been done
- `macos_imageio` HE\* support is undocumented; `probe_decoder()` exists but is **not yet wired
  into `run()`** — a missing capability would currently produce 209 identical errors
- Consider deleting the superseded draft `docs/nef-editor-cli-plan.md` (kept for provenance)
